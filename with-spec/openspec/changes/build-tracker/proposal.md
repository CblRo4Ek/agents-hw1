# Proposal

## Why

Нужен автономный мини-трекер учебных задач на неделю, который работает без CDN, внешних библиотек и API-ключей и позволяет честно проверить ключевые правила: валидацию формы, расчёт прогресса по всем задачам и независимость фильтра от итогов. Проект учебный: важно, чтобы поведение было однозначным, проверяемым и пригодным для приёмочных тестов.

## What Changes

- Реализовать клиентский трекер задач с полями `id`, `title`, `hours`, `done` и стартовым набором: «Чтение» — 2 ч, `done=true`; «Практика» — 4 ч, `done=false`; «Повторение» — 2 ч, `done=false`.
- Добавить операции добавления, удаления и переключения `done`, которые реально изменяют данные и интерфейс.
- Добавить валидацию: название после `trim` непустое; часы — число 0,5–24 с шагом 0,5; пустое значение не считается нулём. Ошибка показывается рядом с полем, введённые данные формы сохраняются.
- Считать прогресс как `round(100 × сумма часов выполненных задач / сумма часов всех задач)`; при отсутствии задач — 0% без `NaN`/`Infinity`.
- Сделать фильтр, который влияет только на видимый список; итоговые часы и прогресс всегда считаются по всем задачам.
- Обеспечить читаемость на ширине 390 px без горизонтального скролла и подписи полей и кнопок.
- Добавить приёмочные тесты T1–T5 на `node:test`, покрывающие стартовые значения, фильтр, ошибки ввода, пустой список и переключение «Практики».
- Опциональное улучшение: сохранение задач в `localStorage` с понятным сообщением и продолжением работы в памяти, если хранилище недоступно.

**Допущение:** выполняется вариант B из `brief.md` — `index.html`, `styles.css`, `app.mjs`, `domain.mjs`, `tests/acceptance.test.mjs`, — а не одностраничный вариант A.

## Capabilities

### New Capabilities

- `tracker`: поведение мини-трекера учебных задач — управление задачами, валидация ввода, расчёт прогресса и итогов, фильтрация списка и доступность интерфейса на мобильной ширине.

### Modified Capabilities

Нет.

## Impact

- Новые файлы в корне проекта: `index.html`, `styles.css`, `app.mjs`, `domain.mjs`, `tests/acceptance.test.mjs`.
- Зависимостей и внешних API нет; запуск тестов — через встроенный `node:test`.
- Опциональный `localStorage` затрагивает только `app.mjs`; при его недоступности базовое поведение не меняется.
- Существующие спецификации отсутствуют, конфликтов с текущим поведением нет.
