# Отчёт: мини-трекер (вариант B, OpenSpec)

## Что сделано

- `index.html`, `styles.css`, `app.mjs`, `domain.mjs` — автономно, без CDN, внешних библиотек и API-ключей.
- `domain.mjs` — чистые функции: стартовые данные, валидация, подсчёт часов, прогресс, фильтр, add/remove/toggle.
- `app.mjs` — состояние, DOM, форма, фильтры, опциональный `localStorage` с сообщением при недоступности и продолжением работы в памяти.
- `tests/acceptance.test.mjs` — приёмочные тесты T1–T5 и дополнительные проверки границ валидации на `node:test`.
- Спецификация, дизайн и задачи — в `openspec/changes/build-tracker/`.

## Правила

- Данные: `id`, `title`, `hours`, `done`. Старт: «Чтение» 2 ч `done`; «Практика» 4 ч; «Повторение» 2 ч.
- Название после `trim` непустое; часы 0,5–24 с шагом 0,5; пустое значение ≠ 0.
- Прогресс = `round(100 × часы done / часы всех)`; нет задач → 0% без `NaN`/`Infinity`.
- Фильтр меняет только видимый список; итоги и прогресс — по всем задачам.

## Фактически проведённые проверки (запускались)

- Команда: `node --test` (Node v24.14.1). Результат: **8 passed, 0 failed**.
  - T1: старт — 8 ч, 2 ч, 25%.
  - T2: фильтр «активные» — 2 задачи, прогресс остаётся 25%.
  - T3: пустое название / пустые / отрицательные часы — ошибка, задача не добавляется.
  - T4: удаление всех — 0 ч, 0%, значение конечно.
  - T5: «Практика» `done` — 6/8 ч, 75%.
  - Дополнительно: границы 0,5 и 24 допустимы; 0, 24,5, 1,25, `abc`, пробел и −0,5 отклоняются; название обрезается по краям.
- Изолированная проверка хранилища без браузера (одноразовый Node-скрипт с поддельным `localStorage`): чтение пустого хранилища даёт стартовый набор; запись и повторное чтение сохраняют задачи; сохранённый пустой список остаётся пустым; повреждённый JSON и неверная структура откатываются на стартовый набор; недоступное хранилище не ломает чтение, а `saveTasks` возвращает `false`.
- Статическая проверка разметки и доступных имён: у полей есть `label` и `aria-describedby`; у фильтров — `aria-pressed` и подпись группы; кнопки удаления и чекбоксы получают `aria-label` с названием задачи; прогресс оформлен как `role="progressbar"`; сообщения об ошибках — `role="alert"`.

## Предложенные ручные проверки интерфейса (НЕ выполнялись, браузер не запускался)

1. Открыть `index.html` через локальный сервер и убедиться, что видно 3 задачи, итог «8 ч», выполнено «2 ч», прогресс «25%».
2. Переключить фильтр на «Активные»: список становится из 2 задач, а итог/прогресс по-прежнему 8 ч / 25%.
3. Отправить пустое название: рядом с полем появляется ошибка, задача не добавляется, введённые данные формы сохраняются.
4. Отправить пустые или отрицательные часы: видна ошибка рядом с полем часов, задача не добавляется.
5. Отметить «Практику»: прогресс становится 75%, выполнено «6 ч».
6. Удалить все задачи: итог «0 ч», прогресс «0%», показано сообщение о пустом списке.
7. Ширина 390 px: нет горизонтального скролла, все поля и кнопки подписаны.
8. Перезагрузить страницу: задачи сохраняются (`localStorage`). При отключённом хранилище видно предупреждение, трекер продолжает работать в памяти.
